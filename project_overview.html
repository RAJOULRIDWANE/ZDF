1. Project Concept

This is a full-stack Garage / Auto-Repair Management System designed to digitize and streamline the entire lifecycle of vehicle repair operations — from client intake, through diagnostics & estimation, to invoicing & delivery.

The system supports 5 distinct user roles, each with a dedicated dashboard, ensuring every stakeholder in the garage workflow has the right tools at their fingertips. The platform also features a public-facing website for potential customers, with full internationalization in 3 languages.

3. System Architecture

Frontend (React SPA) communicates with the Backend (Laravel API) via Axios HTTP requests, authenticated with Sanctum Bearer tokens stored in localStorage.


Request Flow:

React Component → Axios + Token → Laravel Route → Sanctum Middleware → Controller → Eloquent Model → SQLite DB

Backend Controllers: AuthController, ReceptionistController, MechanicController, ClientController, InvoiceController, ServiceController, VehicleController, ForgotPasswordController, ContactDetailsController


Frontend Structure: Role-based page folders (Client-Pages, Mechanic-Pages, Receptionist-Pages, Supervisor-Pages, PartsManager-Pages) + shared components (Navbar, DashboardNavbar, Footer) + public pages

5. Repair Lifecycle (Workflow)

Pending → Diagnosing → Estimate Sent → Estimate Accepted → In Progress → Completed → Delivered

Alternative paths:

Estimate Sent → Negotiation Requested → In Progress
In Progress → Waiting for Parts → In Progress
Pending → Canceled
Status Set By Description
Pending Receptionist Job has been created and assigned to a mechanic
Diagnosing Mechanic Mechanic is actively diagnosing the vehicle
Estimate Sent Mechanic Estimate with services and costs has been sent to the client
Estimate Accepted Client Client has approved the estimate
Negotiation Requested Client Client has requested a discount on the estimate
In Progress Mechanic / Receptionist Repair work is actively underway
Waiting for Parts Mechanic Work is paused while waiting for parts
Completed Mechanic Repair is finished; client is notified
Delivered Receptionist Vehicle has been returned to client after payment
Canceled Receptionist Job has been canceled

6. Data Model

The database uses SQLite with 14 migrations. Core entities are linked through foreign keys and many-to-many pivot tables.

👤 User (users)
  • id PK
  • name string
  • email string, unique
  • password hashed
  • role client | mechanic | receptionist | supervisor | parts_manager
  • phone string
  • is_verified boolean
🚗 Vehicle (vehicles)
  • id PK
  • user_id FK → users
  • license_plate string
  • make string
  • model string
  • year int
  • type string
🔧 Repair (repairs)
  • id PK
  • vehicle_id FK → vehicles
  • mechanic_id FK → users
  • description text
  • mechanic_notes text
  • status string (10 statuses)
  • is_diagnostic boolean
  • cost / original_cost decimal
  • discount_amount decimal
  • negotiation_status string
  • invoice_number string
  • date_entry / date_end date
🛠️ Service (services)
  • id PK
  • name string
  • zone string (engine, body, lights...)
  • price decimal
📦 Part (parts)
  • id PK
  • name string
  • zone / category string
  • price decimal
  • stock_quantity int
  • reference_number string
🧾 Invoice (invoices)
  • id PK
  • repair_id FK → repairs
  • invoice_number string
  • total_amount decimal
  • paid_amount decimal
  • status Unpaid | Paid
  • payment_method Cash
  • paid_at datetime

Pivot Tables

Table Connects Extra Columns

7. Authentication & Security

Feature Implementation
Registration Email + password. User created as is_verified: false. 6-digit OTP emailed.
OTP Verification OTP stored in email_verifications table. Expires in 10 minutes. One-time use.
Resend OTP Deletes old OTP, generates new 6-digit code, re-sends email.
Login Validates credentials + verification status. Returns Sanctum personal access token.
Route Protection React ProtectedRoute component checks token + role. Redirects if unauthorized.
Change Password Validates current password before allowing update.
Forgot Password Email-based reset link with a secure token.
Staff Creation API endpoint for creating mechanic, receptionist, supervisor, or parts_manager accounts.

11. Notable Features

🚗 Repair Visualizer

An interactive car silhouette (accessible from the receptionist dashboard) that maps service zones onto a visual diagram. Each zone (engine, body, lights, wheels) highlights based on the repair's associated services, providing an at-a-glance view of what areas of the vehicle are being worked on. Currently supports sedan vehicle type with front, back, top, and bottom views.

📄 PDF Generation (Client-Side)

Both estimates and invoices are generated using jsPDF directly in the browser:

  • Professional layout with garage branding and logo
  • Service line items with descriptions and prices
  • Parts breakdown with quantity and unit price columns
  • Discount information (if negotiated)
  • Subtotal, discount, and final total calculations
  • Available from both client and receptionist dashboards

💰 Price Negotiation System

A two-step negotiation flow between clients and receptionists:

  • Client requests a discount after receiving an estimate
  • Repair status changes to "Negotiation Requested"
  • Receptionist reviews and approves (5% automatic discount) or rejects
  • Original price is preserved; discount amount tracked separately
  • Work automatically begins after receptionist decision

🔔 Notifications

When a mechanic marks a job as completed, the vehicle owner (client) is automatically notified via Laravel's built-in notification system using the RepairCompleted notification class.

🔍 Diagnostic Workflow

Jobs can be flagged as diagnostic. When a mechanic submits an estimate for a diagnostic job, the system automatically ensures the "General Diagnostic" service (50 MAD) is included, even if the mechanic forgot to select it. The is_diagnostic flag persists throughout the repair lifecycle.
